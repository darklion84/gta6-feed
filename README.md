# GTA6 HOT: лента коротких роликов (gta6hot.com)

Автоматический агрегатор коротких роликов из GTA 6. Ничего не скачивает и не
перезаливает: хранит только ссылки и показывает ролики через официальные плееры
площадок.

- каждые 30 минут ищет свежие и популярные YouTube Shorts (до 90 секунд);
- принимает ссылки на TikTok и Instagram Reels, которые вы присылаете боту;
- отсекает дубли и перезаливы за последние 72 часа;
- присылает кандидатов вам в личку бота с кнопками «В канал» / «Пропустить»;
- одобренное постит в Telegram-канал и на сайт (GitHub Pages).

## Модерация

Чтобы бот мог вам писать, откройте его и нажмите **Start**. Сборщик
запускается раз в 10 минут и присылает кандидатов пачками.

С обработчиком на Cloudflare (см. ниже) кнопки срабатывают мгновенно: «В
канал» сразу публикует пост и удаляет сообщение с кандидатом, «Пропустить»
просто удаляет. Сообщение осталось на месте: значит, нажатие не прошло,
нажмите ещё раз.

Без обработчика бот узнаёт о нажатии только при следующем запуске сборщика
(до 10–15 минут) и тогда же удаляет сообщение.

## Мгновенные кнопки: обработчик на Cloudflare

В папке `worker/` лежит небольшой обработчик для Cloudflare Workers
(бесплатный тариф). Telegram присылает ему каждое нажатие и сообщение, он
реагирует сразу, а сделанное складывает в очередь, которую сборщик забирает
при запуске. Он же раз в 10 минут и после каждого вашего действия запускает
сборщик на GitHub, так что расписание GitHub остаётся только запасным ходом.

Нужны три секрета в репозитории:

| Имя | Что это |
|---|---|
| `CLOUDFLARE_ACCOUNT_ID` | Account ID из раздела Workers & Pages |
| `CLOUDFLARE_API_TOKEN` | токен по шаблону «Edit Cloudflare Workers» |
| `DISPATCH_TOKEN` | fine-grained токен GitHub: только этот репозиторий, Actions: Read and write |

Выкладка идёт сама (`.github/workflows/worker.yml`) при каждом изменении
`worker/` или вручную: Actions → worker → Run workflow. Она же привязывает
бота к обработчику. Если токен GitHub истечёт, бот напишет вам об этом;
кнопки при этом продолжат работать, а сайт будет обновляться по запасному
расписанию.

Отключить обработчик: удалить `data/worker_url.txt` и снять привязку бота
(`deleteWebhook`), после этого сборщик снова опрашивает Telegram сам.

Пока 10 кандидатов ждут ответа, новые не присылаются. Без ответа за 12 часов
кандидат снимается. Ссылки, которые вы прислали сами, идут в канал без
модерации. Выключить модерацию: `MODERATION = False` в `config.py` (и поднимите
пороги, как там написано).

Сервер не нужен: всё работает на бесплатных GitHub Actions и GitHub Pages.

## Запуск (минут 20)

1. **Telegram.** Создайте канал. В @BotFather создайте бота и сохраните токен.
   Добавьте бота в канал администратором с правом публикации. Свой числовой ID
   узнайте у @userinfobot.
2. **YouTube.** В Google Cloud Console создайте проект, включите
   «YouTube Data API v3», создайте API key.
3. **GitHub.** Создайте **публичный** репозиторий и загрузите в него все файлы
   из архива (включая папку `.github`).
4. **Секреты.** Settings → Secrets and variables → Actions → New repository secret:

   | Имя | Значение |
   |---|---|
   | `YOUTUBE_API_KEY` | ключ из шага 2 |
   | `TELEGRAM_BOT_TOKEN` | токен бота |
   | `TELEGRAM_ADMIN_IDS` | ваш числовой ID (несколько через запятую) |

5. **Сайт.** Settings → Pages → Source: **GitHub Actions**.
6. **Адреса.** В `config.py` впишите `SITE_URL` (адрес Pages со слэшем в конце),
   `TELEGRAM_URL` и `TELEGRAM_CHANNEL` (`@имя_канала`).
7. **Первый запуск.** Actions → feed → Run workflow. Дальше оно работает само.

Любой секрет можно не задавать: без ключа YouTube пропускается поиск, без
токена бота ролики идут только на сайт.

## TikTok и Instagram

У этих сетей нет официального поиска для таких проектов, поэтому ролики
добавляются вручную: пришлите боту в личку ссылку, после неё можно дописать
подпись.

```
https://www.tiktok.com/@author/video/7300000000000000000 Cop chase gone wrong
```

Бот ответит, что ролик в очереди, и он выйдет при ближайшем запуске. Бот
слушает только ID из `TELEGRAM_ADMIN_IDS`, остальным даже не отвечает.
Запасной способ: строка в `links.txt`.

Понимает ссылки YouTube, TikTok, Instagram и на посты публичных
Telegram-каналов (`https://t.me/channel/123`).

### Пересылка постов боту

Можно просто переслать боту пост из Telegram:

- если в посте есть ссылка на YouTube, TikTok или Instagram (в том числе
  спрятанная под словом), в ленту пойдёт она;
- если это видео из публичного канала, бот перешлёт его в ваш канал штатной
  пересылкой Telegram (с пометкой «переслано из …»), а на сайте пост
  встроится виджетом Telegram;
- если источник закрытый (приватный канал, личный чат), пост выйдет только
  в канале: встроить его на сайт нельзя.

Сам бот видео не скачивает и не перезаливает.

## Поиск, подборка дня и карточка канала

- **Страницы роликов** (`docs/c/<сеть>-<id>/`). У каждого ролика ленты есть своя
  страница с названием, плеером и разметкой видео: её индексируют поисковики, а
  мессенджеры строят по ней превью. Ссылки из канала и кнопки «Поделиться»
  заканчиваются на `#feed`: с этой меткой страница сразу открывает ленту на нужном
  ролике. Адреса всех страниц перечислены в `docs/sitemap.xml`. Чтобы Google
  нашёл их быстрее, один раз добавьте сайт в
  [Search Console](https://search.google.com/search-console) и укажите там
  `https://gta6hot.com/sitemap.xml`.
- **Подборка дня.** Раз в сутки (после `TOP_HOUR_UTC`) в канал уходит один пост
  с пятью самыми просматриваемыми роликами за последние 24 часа. Тот же список
  показывают страница `/top/` и кнопка «Top» в ленте. Если роликов с просмотрами
  меньше `TOP_MIN_COUNT`, подборка в этот день не выходит. Выключить:
  `TOP_ENABLED = False`.
- **Карточка канала.** В ленте сайта после восьми роликов, а дальше через каждые
  двенадцать, показывается приглашение в Telegram-канал. Тем, кто уже перешёл в
  канал, она больше не показывается.

## Автоматический режим («вето»)

Чтобы не просматривать каждый ролик вручную, можно включить `AUTO_MODE` в
`config.py`. Тогда в личку бота приходят только ролики, готовые выйти сами:

1. ролику не меньше 6 часов и у него не меньше 20 лайков на 1000 просмотров;
2. это не дубль и не повтор темы (`TOPIC_LIMITS`);
3. модель посмотрела четыре кадра ролика и признала его чистым геймплеем
   (`feed/vision.py`; ролики без игры и с тяжёлыми вставками отсекаются молча).

Кандидаты приходят равномерно, примерно по одному в 40 минут (`AUTO_MAX_PER_DAY`).
Под кандидатом написано, во сколько он выйдет. Если за два часа не нажать
«Пропустить», ролик публикуется сам; «В канал» публикует сразу. Остальные
находки модератору не показываются. Свои ссылки и пересланные посты работают
как раньше.

Проверка кадров включается отдельно: `AUTO_VISION = True`. Модели нужен ключ в
секретах репозитория: `ANTHROPIC_API_KEY` или `GEMINI_API_KEY`; без ключа при
включённой проверке возвращается ручная модерация. Пока `AUTO_VISION = False`,
третий пункт не выполняется: ролики без игры и со вставками убирает модератор.
Если модель перестанет отвечать, бот напишет об этом, а кандидаты пойдут на
ручную модерацию. Проверить модель на размеченных роликах: Actions → vision.

## Анонсы в Bluesky и Threads

Каждый ролик, вышедший в ленте, и подборка дня могут сами уходить короткой
записью со ссылкой на сайт в другие сети. Сеть включается, когда в
Settings → Secrets and variables → Actions появляются её секреты:

- **Bluesky.** Заведите аккаунт на [bsky.app](https://bsky.app), затем в
  Settings → Privacy and security → App passwords создайте пароль приложения.
  Секреты: `BLUESKY_HANDLE` (например `gta6hot.bsky.social`) и
  `BLUESKY_APP_PASSWORD`.
- **Threads.** Нужен аккаунт Threads и приложение в
  [кабинете разработчика Meta](https://developers.facebook.com/apps/) со сценарием
  Threads API и правами `threads_basic` и `threads_content_publish`. Себя
  добавьте как Threads Tester (App roles → Roles) и примите приглашение в
  настройках Threads (Account → Website permissions). Долгоживущий ключ
  доступа положите в секрет `THREADS_TOKEN`. Ключ живёт 60 дней, сборщик раз в
  неделю продлевает его сам.

Если сеть перестанет принимать ключ, бот напишет об этом в личку. Темп и теги
задаются в `config.py` (`SOCIAL_*`).

## Настройка

Всё в `config.py`, с комментариями. Главное:

- `QUERIES`, `MUST_MATCH`, `STOP_WORDS`: что искать и что отбрасывать;
- `POPULAR_MIN_VIEWS`, `FRESH_*`: пороги «уже популярный» и «свежий, быстро растёт».
  В первые дни после релиза просмотры огромные; если постов слишком много,
  поднимайте пороги, если мало, опускайте;
- `MAX_POSTS_PER_RUN`, `MAX_PER_CHANNEL_PER_DAY`: частота постов;
- `SEARCH_LANGUAGE`: какой язык поиск ставит выше (по умолчанию английский).

## Как устроено

```
feed/__main__.py   один проход: ссылки -> поиск -> статистика -> публикация -> feed.json
feed/youtube.py    YouTube Data API
feed/telegram.py   посты в канал и приём ссылок
feed/dedup.py      дубли: длительность ±1 с плюс похожее название или обложка
feed/pages.py      страницы роликов, подборка дня, карта сайта
feed/vision.py     проверка кадров моделью (автоматический режим)
feed/topics.py     повторы темы: один глитч на язык
feed/social.py     анонсы в Bluesky и Threads
feed/channel_setup.py  разовая настройка названия и описания канала (workflow channel)
docs/index.html    сайт, читает docs/feed.json
data/db.json       база (создаётся сама, хранит 14 дней)
```

Локальный запуск: `pip install -r requirements.txt`, задать переменные окружения
из шага 4, затем `python -m feed`. Тесты: `python -m unittest tests.test_offline`.

## Что стоит знать

- **Квота YouTube.** По умолчанию 100 поисков в сутки, сборщик тратит до 95.
  Если нужно больше, квоту можно запросить у Google.
- **Расписание GitHub** неточное: запуск может задержаться на 5–20 минут.
- **Свой домен** подключается в Settings → Pages → Custom domain.
- **Версии actions** в `.github/workflows/feed.yml` стоит поднять, если GitHub
  покажет предупреждение об устаревании.
- **Правила площадок.** Проект не связан с Rockstar Games и Take-Two. Не
  используйте их логотипы и арт. Перед включением рекламы прочитайте условия
  YouTube API и встраивания TikTok и Instagram.
